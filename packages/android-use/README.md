# @ohmycode/android-use

本机 Android 设备集成，支持通过 ADB 连接真机、已有模拟器及内置模拟器。包不依赖桌面应用目录、React 或 Flask；使用 Node 进程和文件能力，声明为 Electron 平台包，不提供给 mobile。

## 设备选择

设置 → 实验室中刷新并选择当前设备。USB 手机需要开启 USB 调试并在手机上授权；Windows 可能需要厂商驱动。网络设备需先开启 ADB 网络调试，再填写地址和端口连接；仅支持已有可连接端点，不自动配置无线配对。

Agent 只操作设置中选择的设备，没有选择设备的工具参数。开始操作后由当前会话独占，使用期间不能切换；本轮完成、失败或停止后延迟 3 分钟关闭连接并释放占用，期间同一会话开始新一轮会取消旧计时，待新一轮结束再计时。宽限期仍保持独占。显式停止设备或退出应用仍立即关闭。其他会话不能查看画面或控制设备，面板显示占用错误页。设备断线会报错，不自动换设备。外部设备只需 ADB，可单独安装 Platform Tools，无需下载系统镜像。内置模拟器是需手动选择的兜底方案。

外部设备的断开只释放 OhMyCode 的视频、控制及会话占用，不关闭手机、其他模拟器或共享 ADB。内置模拟器仍由应用管理完整生命周期。外部设备的视频与输入兼容性需要按设备实际验证，不能保证所有第三方模拟器可用。

外部模拟器或网络设备重启后，连接/重试会重新读取 ADB 状态；所选 `host:port` 不在线时，仅向这个地址执行一次 `adb connect`，再确认是否上线并更新设备列表状态。不扫描端口、不改选设备、不重启共享 ADB；USB 设备和未授权设备不会套用网络重连。

进入实验室会自动刷新设备列表；点击刷新也会重新查询 ADB，并尝试恢复已保存的离线网络地址。设备使用期间允许刷新状态，但不会重新配置当前连接、切换目标或释放会话占用。

## 当前范围

- 支持 Windows 和 macOS，检测本机 SDK 中的 Emulator、Platform Tools、原生 CPU 架构手机镜像和硬件加速。
- 内置模拟器只管理 OhMyCode 创建的一台 AVD，使用独立 ADB server 端口；外部设备使用共享 ADB 并显式指定 serial。
- 支持启动、停止、UI 层级、截图、节点/选择器点击、坐标滑动、导航按键、Unicode 文本设值及条件等待。
- 截图使用现有 Runtime 图像结果结构；只有视觉模型能获得截图工具，文本模型可读取 UI 层级。
- 用户鼠标走独立的 scrcpy 控制通道，实时传递按下、每段移动轨迹和抬起，支持长按、拖动、曲线和绘图；失焦、取消、收起或切换窗口会释放按压。仅支持单指鼠标，不把复杂手势扩展为 Agent 工具。
- 工具仅在环境检查通过且用户启用后注册；执行时再次检查启用状态。关闭面板不停止设备，停止设备不删除应用数据。

## 安装和数据

支持从 Google 官方源按需安装，也可选择已有 SDK。安装前由用户明确确认许可，不自动代为接受；不镜像分发 SDK。默认检测 `ANDROID_HOME`、`ANDROID_SDK_ROOT` 及系统常用 SDK 目录。

`install/manifest.ts` 固定 Emulator、Platform Tools、Android 15 基础镜像的版本、大小和官方 SHA-1 校验值（来自官方 SDK 仓库清单），不在安装时解析 latest。下载直接流式落盘，使用宿主注入的网络实现；桌面端注入 Electron `net.fetch` 以遵循系统代理。解压也使用流式处理，保留 Unix 可执行权限，不传播 Windows 只读属性；拒绝越界路径和外部符号链接。

安装器只替换带本应用组件凭据的目录，以临时目录校验、解压后原子发布单个组件，失败不会覆盖现有安装。重试复用已完成组件，未完成 ZIP 不做字节级断点续传。安装文件默认位于 `<userData>/android/sdk/`，自选位置则使用该位置的 `OhMyCodeAndroid/sdk/`；临时下载成功后清理。

桌面宿主保存本机设置到 `<userData>/android.json`，设备数据位于 `<userData>/android/avd/OhMyCode.avd/`，不修改 SDK 自带镜像或用户已有 AVD。设置不随账号同步。

Android 面板通过 scrcpy 3.3.4 的设备端服务输出 H.264，客户端使用 Chromium WebCodecs 解码，不使用截图轮询。首次打开画面从官方 GitHub Release 下载约 91KB 服务文件，验证固定 SHA-256 后缓存到 `<userData>/android/video/`，后续可离线使用；无需安装桌面版 scrcpy、Java 或 FFmpeg。该服务采用 Apache-2.0 许可，来源见 https://github.com/Genymobile/scrcpy/tree/v3.3.4 。

控件自动化使用 openatx UIAutomator2 3.7.1 的设备端 JAR。首次连接从固定的官方 PyPI wheel 提取约 3.7MB JAR，分别核对 wheel 和 JAR 的 SHA-256，缓存到 `<userData>/android/automation/`。电脑不需要 Python/Java，不安装辅助 APK、输入法或修改用户无障碍设置。连接时通过 ADB 部署独立进程与随机端口，停止时只清理本应用创建的进程、转发和设备端临时 JAR，不重启共享 ADB。下载使用宿主网络设置；本机 RPC 使用 loopback，不走外部代理。

注意：上游设备端 HTTP 服务没有认证，且监听设备网络接口。随机端口不是安全隔离；不要在不可信局域网中的真机上保持运行，也不要将设备服务端口对外转发。结束任务后应停止连接。源码来源与 MIT 许可见 [第三方说明](THIRD_PARTY_NOTICES.md)。

面板支持拖动左侧边界、切换独立窗口和返回面板，均操作同一台设备。隐藏面板或切换会话只关闭视频连接，不停止设备；Agent 截图工具独立按需执行。启动必须指定会话 ID，设备启动期间和运行期间均由该会话独占；投屏、控制和 Android 工具均检查所有权，其他会话不能查看、操作或关闭它。独立窗口绑定打开它的会话，不跟随设备所有者切换。每个 Turn 结束时，Runtime 工具注册表通过 Android 插件安排 3 分钟延迟释放，覆盖完成、失败及取消；同一会话创建下一轮工具插件时取消旧计时。用户点击面板底部关机按钮或工具显式 stop 会立即释放并取消计时。启动失败和设备异常退出同样释放占用。首次启动最长等待约两分钟，可通过对话面板关机按钮取消。退出应用会先停止自有模拟器，再关闭自有 ADB server。

## 模块

`android_snapshot` 读取常驻 UIAutomator 服务，返回紧凑节点、`snapshotId` 和 `screen`，不再运行 `adb shell uiautomator dump` 或写入中间 XML 文件。快照与截图的 `screen` 包含当前旋转方向下的屏幕像素宽高、rotation 和坐标约定。沿用原有空布局省略规则，不额外做语义折叠或按应用过滤；大结果交由现有 `resultRef` 分页与检索处理。只输出禁用状态 `enabled:false`，默认启用状态省略；实际操作仍检查实时控件的 enabled 状态。`editable` 仅在底层明确提供时输出布尔值，未提供则省略（未知），不依据控件类名推断，不逐节点输出 `null`；当前固定版本的层级通常不提供此属性。`checkable:true` 的节点始终包含 `checked:true/false`。其他压缩布尔标记仍仅在为 true 时输出。

`android_act` 支持 `selector` 或 `snapshotId + nodeId` 定位。选择器支持 resourceId、text、textContains、description、className、packageName、focused，组合条件按 AND 匹配。操作前读取当前层级检查唯一性，再交给原生服务使用当前控件位置操作；不会默认选第一个重复控件。歧义时返回 `error:android_node_ambiguous`、新的 `snapshotId`、`totalMatches`、`truncated` 和最多 10 个候选，每个候选带节点属性、bounds 和父节点上下文；调用方据此补充唯一条件，不自动选择或重试。

节点 ID 是快照内的位置序号，不是跨快照稳定身份，不使用内容哈希伪装持久 ID。新快照、执行操作、用户输入、断线或关闭都会使旧引用失效；节点操作前还会检查引用节点及其祖先的属性、bounds 和旋转方向是否发生变化，变化则要求重新观察。该检查不是原子布局锁，不保证检测到所有应用内部变化。文本节点可向上寻找可点击父节点。没有控件属性的游戏等页面仍使用截图和坐标操作，快照无法保证没有键盘或覆盖层遮挡。

点击、滑动和按键返回的 `executed` 仅表示指令已执行，不表示达到业务目标；不再返回恒为 false 的 `verified`。`text` 设置（替换）目标输入框的 Unicode 文本，无目标时使用当前聚焦控件。返回 `executed`、回读 `text` 和 `textMatched`，后者仅表示回读文字与输入一致，不代表应用接受、计算完成、提交成功或持久化。不推测 `accepted`，不增加自动操作闭环。回读有歧义时返回 `executed:true`、`textMatched:null` 及歧义候选，不能误认为文字未写入而重复执行。控件可能把 hint 作为空值的可访问文字，因而清空后的 `textMatched` 可能为 false。用户在投屏画布上的普通按键则直接走 scrcpy 输入通道，不执行整框文本替换。

`wait` 支持选择器的 `present/absent`，默认 15 秒，可配置 0–120 秒。采用最长 500ms 的原生等待片段，可取消；超时返回 `matched:false`，RPC/读取失败仍返回错误，不被当成节点消失。等待不产生重复截图或模型往返。

条件等待不是 sleep，也不代表应用已就绪。只使用观察有依据的选择器，不能从截图猜测可访问文字或包名（`packageName` 精确匹配，不匹配前缀）。超时后重新观察、诊断，不原样延长条件等待。游戏、画布等视觉页面使用截图和坐标；需要等待过渡时，`android_screenshot` 可传 `delayMs`（整数 0–5000，默认 0），在同一次调用中延迟后截图。任务取消、设备停止或断线会中断延迟，不继续截图。

操作说明要求按当前目标观察，不预先遍历所有应用；操作无变化时先诊断再重试，保存后回读，缺少必需应用时报告而不擅自换成其他数据写入位置。

### 视觉坐标与观察历史

截图返回 `screenshotId`、图片 `width/height` 和设备 `screen`。Agent 的坐标点击/滑动必须携带该 ID，并指定 `coordinateSpace: "image-pixels"` 或 `"normalized-1000"`；不根据数值猜测单位。图片像素分别按横纵比例映射到设备像素；归一化值 0–1000 表示整个画面，1000 映射到最后一个有效像素。实际执行坐标、图片和设备尺寸随结果返回，复用原有工具详情和上下文调试入口。

新截图、控件操作、导航按键、人工输入或断线会使旧截图引用失效；读取节点快照不改变截图引用。坐标动作还会检查实时尺寸和旋转方向。坐标动作自身不自动截图，可复用同一画面中仍有效的位置，但导航、滚动或弹层改变目标后必须重新观察。这不是页面不变保证，不检查业务完成。原始截图暂不缩放，后续尺寸策略需要命中率、延迟和 token 对比后确定。

服务端在当前 Turn 中仅保留最近两批工具图片作为视觉输入，同一批的多张图整体保留；更早批次转为文字和图片引用。原始事件、MinIO 图片、用户附件和界面回显不变，旧图片可通过现有图片查看工具重新加载。此策略独立于文本上下文压缩，避免等待压缩阈值才处理累积截图。上下文实际由 worker 构造，更新此逻辑时需要同步更新 API 和 worker，仅重启 API 不会使运行中的 worker 加载新策略。

工具说明优先使用足够的现有观察，不默认同时获取节点树和截图；已知控件使用条件等待，纯视觉页面使用延迟截图，不增加逐步自动验证或额外模型。

- `environment.ts`：SDK 和加速能力检查。
- `android-host.ts`：目标连接、会话所有权及设备操作。
- `adb.ts`：设备发现、网络连接与目标参数。
- `managed-emulator.ts`：自有 AVD、模拟器进程及独立 ADB 生命周期。
- `command.ts`：受控子进程、坐标手势及导航；不再提供 shell 文本输入。
- `snapshot.ts`：UI XML 解析、空布局过滤与操作祖先关联。
- `index.ts`：Runtime 工具插件。
- `install/`：固定版本清单、虚拟化预检、流式下载与解压、组件安装；不依赖 Electron UI。
- `automation/`：固定版本资源、设备端服务生命周期、选择器协议及控件动作/等待。

模拟器真实启动、应用兼容性及 Windows/macOS 画面操作需要在安装 SDK 的设备上验收。单元测试不代替这部分验收。
